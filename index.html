Linux Kernel

基础原理 = 数据结构与算法基本功(核心原理图 + 可运行 Go 实现,取材 hello-algo 并逐一源码核实);是读懂上层系统源码前的地基。

数据结构线性表 · 哈希 · 树 · 堆 · 图 —— 一切容器的地基

数组与链表连续内存换随机访问，离散节点换增删灵活——两种最基础的线性布局，是一切容器的地基。 栈与队列只在端点操作的受限线性表：栈 LIFO、队列 FIFO、双端队列两头皆可——用数组或链表都能承载。 哈希表用哈希函数把键直接映射到桶下标，换来平均 O(1) 增删查；代价是冲突处理与扩容 rehash。 树层次化的分叉结构：遍历给出访问秩序，二叉搜索树给出有序 O(log n) 查找，AVL 用旋转守住平衡。 堆用数组隐式表达的完全二叉树，只保证父子间偏序；堆顶恒为极值，是优先队列与 TopK 的引擎。 图顶点与边的任意关系网：邻接矩阵稠密快查、邻接表稀疏省空间；BFS 逐层扩散、DFS 一路到底。

算法搜索 · 排序 · 分治 · 回溯 · 动态规划 · 贪心 —— 解题范式

搜索在数据里定位目标：无序只能线性 O(n)，有序可二分 O(log n)，用哈希把查找摊到 O(1)。 排序把序列变有序的经典战场：比较类下界 O(n log n)，非比较类靠桶/计数/基数在特定分布下线性突破。 分治把问题拆成同构子问题、递归求解、再合并——分治是二分、归并、快排、树形构造背后的统一骨架。 回溯在解空间树上深度探索：尝试→递归→撤销，配合剪枝把指数搜索裁到可行——全排列、子集、N 皇后同一套框架。 动态规划有重叠子问题+最优子结构时，用状态转移方程记住子解、消除重复计算——从爬楼梯到背包、编辑距离一脉相承。 贪心每步都取当下最优、不回头——正确性依赖「贪心选择性质」，零钱贪心的反例正说明它并非总对。

系统视角 = 系统设计模式为何选(分片/缓存/限流背压/消息队列/服务发现/熔断幂等重试,每个模式下的变体都显式点名真实项目做对比);区别于「主题视角」纵向钻透单个机制在多项目中的实现。

分片与哈希分片把「一张表」拆成「可独立搬动的单元」，取舍轴是加减节点时要不要搬动全量数据——固定哈希槽最简单也最刚性，一致性哈希环最柔性。
  • 固定哈希槽 Fixed Hash Slots
  • 一致性哈希环 Consistent Hash Ring
  • 范围+哈希两级 Range + Hash
 复制策略复制把「一份数据」变成「多份副本」以换容错，主从/多主/无主三种拓扑在「写去哪」「读多新」「丢多少」三轴上各有取舍。
  • 主从 Primary-Standby
  • 多主 Multi-Master
  • 无主 Leaderless（概念参考）
 缓存模式缓存拿命中率换延迟，核心矛盾在「命中前谁去源站取」与「写后何时让缓存看见新值」——两条路径分别决定了读穿透与写回的形状。
  • 读穿透+回填 Read Path
  • 写回 Write-Back
 限流与背压系统扛不住流量有两种姿势：在门外拒绝（限流）或在内部把压力向上游传导（背压）——前者保护自己、后者保护全链路。
  • 边缘拒绝 Rate Limiting
  • 内部传导减速 Backpressure
 消息队列模式消息队列把「谁发」与「谁收」解耦，发布订阅/竞争消费者/投递语义三个维度分别回答「广播给谁」「谁分摊」「丢不丢/重不重」。
  • 发布订阅 Publish-Subscribe
  • 竞争消费者 Consumer Group
  • 投递语义 Delivery Semantics
 服务发现服务发现的核心是「怎么知道一个节点还活着」——租约心跳与会话临时节点是同一个 TTL 思想的两种实现外壳。
  • 租约心跳 Lease
  • 会话临时节点 Ephemeral Session
 熔断幂等重试故障是常态不是异常：熔断阻止故障扩散、幂等让重试安全、重试让瞬时故障自愈——三者环环相扣，少一个都不完整。
  • 熔断状态机 Circuit Breaking
  • 幂等键去重 Idempotency
  • 安全重试 Safe Retry
