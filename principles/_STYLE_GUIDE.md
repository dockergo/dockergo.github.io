# 架构原理 SVG / MD 风格指南（内部工作文件，非产出，不会被 gen.py 读取，完工后可删）

## SVG 规范（严格复用 topics/consensus、topics/transaction 现有 SVG 的视觉语言）

- 根标签：`<svg xmlns="http://www.w3.org/2000/svg" width="W" height="H" viewBox="0 0 W H" font-family="-apple-system,BlinkMacSystemFont,'SF Pro Display','Helvetica Neue','PingFang SC','Microsoft YaHei',sans-serif">`
- 尺寸：生态架构总图（00）用较大画布（约 1140×680 ~ 1300×792）；单个变体机制图约 1100×600 ~ 1150×650；对比图（CMP）约 1120×640 ~ 1160×680。按内容密度自行微调，不必强求一致到像素。
- `<defs>` 固定包含阴影滤镜：
  ```
  <filter id="soft" x="-20%" y="-20%" width="140%" height="140%"><feDropShadow dx="0" dy="1.5" stdDeviation="4" flood-color="#1d1d1f" flood-opacity="0.08"/></filter>
  ```
  外加按用到的颜色定义箭头 marker（id 用颜色首字母，如 aB=蓝 aG=绿 aP=紫 aA=琥珀 aR=红 aT=青 aO=橙），例如：
  ```
  <marker id="aB" viewBox="0 0 10 10" refX="8" refY="5" markerWidth="7" markerHeight="7" orient="auto-start-reverse"><path d="M0,0 L9,5 L0,10 z" fill="#4a7fd0"/></marker>
  ```
- 背景：`<rect width="W" height="H" fill="#fbfbfd"/>`（纯白背景——深色主题由外层 CSS `filter:invert(.925) hue-rotate(180deg) saturate(.86)` 自动反色，SVG 本身只画浅色版，不要自己做深色版）。
- 判型标题带（每张图必须有）：
  - 主标题 `x=30 y=32 font-size=15 font-weight=700 fill=#1d1d1f` —— 一句话讲完这张图的核心结论（不是"这张图是关于什么"，是"结论是什么"）。
  - 副标题 `x=30 y=53 font-size=10.5 fill=#6e6e73` —— 补一层机制性细节。
  - 图例行（y≈80-86）：若图中有 ≥2 种语义连线，用彩色短线+箭头+文字标注。
  - 图例下方一条 `<line stroke="#e4e7ec"/>` 分隔线，之后才是图body。
- 配色家族（背景/边框/主文字/副文字四元组，照抄数值，不要自造新色）：
  | 家族 | 强调线/箭头 | 卡片底 | 卡片边 | 主文字 | 副文字 |
  |---|---|---|---|---|---|
  | 蓝 | `#4a7fd0` | `#eaf1fb` | `#c6d9f2` | `#20375e` | `#3a4a63`/`#5a7099` |
  | 绿 | `#2f9e6e` | `#eaf6f0` | `#bfe3d1` | `#2f6b4e` | `#3f8a63` |
  | 紫 | `#8a5cae` | `#f4eefb` | `#dcc9ef` | `#6f3ea8` | `#5a3a7a` |
  | 琥珀 | `#c99a3a` | `#fbf3e2` | `#ecd6a8` | `#8a6417` | `#7a5a1a` |
  | 红 | `#d1544a` | `#fbe6e3` | `#e8a79f` | `#8a4038` | `#b06a60` |
  | 青（新增，风格延续）| `#2aa0a4` | `#e4f4f4` | `#bfe1e1` | `#1d6b6e` | `#4a8a8c` |
  | 橙（新增）| `#d9772f` | `#fbeee2` | `#ecc6a8` | `#9a5f1c` | `#b0854a` |
  | 中性卡片 | — | `#ffffff` | `#e4e7ec` | `#1d1d1f`/`#4a4a4f` | `#6e6e73`/`#8a97ab`/`#a1a1a6` |
  | 中性灰底（对比图维度标签列）| — | `#f6f7f9` | `#e4e7ec` | `#1d1d1f` | `#8a97ab` |
- 圆角：大容器 `rx=12~14`，内部小卡片 `rx=9~10`。
- 字号阶梯：主标题 15 / 副标题 10.5 / 区块标题 12~13(bold) / 卡片标题 10.5~12.5(bold) / 正文 9~9.5 / 细字注解 8.5~9。
- 对比图（`_CMP`）固定版式：顶部一行按「变体/项目」着色表头（每个真实项目一色，用上表家族），左侧一列灰底维度标签（4 个对比维度左右），中间 N×M 网格每格白卡片（粗标题+2~3 行细节），底部一条 `filter="url(#soft)"` 的白色横幅「一句话总结」跨全宽。
- 所有文字用中英混排技术语域：精炼、无废话、专业术语用 `<tspan>` 或直接嵂入，真实类名/函数名尽量保留原文（大小写、下划线原样）。
- **禁止**编造本指南「已验证事实」之外的新技术细节；如需连接性描述（图的布局措辞），保持结构性、不下新论断。

## MD 文件规范（parse_prose() 解析约定）

- 纯文本文件，每节以单独一行 **`@标记名`**（小写英文/数字，无其他字符）开头，标记名之后的所有行（直到下一个 `@标记` 或文件末尾）都属于这一节。
- 节内正文：连续中文散文，空行=分段。支持行内 `**粗体**`、`` `代码` ``、`[文字](https://url)` 三种 markdown，会被转成 `<b>`/`<code>`/`<a>`。
- 每个变体机制一节，标记名 = 该机制 ID 小写（如 `C1` → `@c1`）。另有 `@eco`（生态架构总图配文）与 `@cmp`（对比图配文，可以稍长，覆盖跨项目取舍）。
- 文末 `@refs` 一节：3~6 条权威参考，每条独占一段（空行分隔），格式 `[标题（作者/机构，年份/来源）](URL)` 或纯文字引用（书籍/论文无稳定链接时）。**只用你在下方"已验证事实"或本文明确给出的 URL / 论文名，不要为求好看编造新的深链接**（本会话已实测：编造的深链接会 404）。若不确定某 URL 是否稳定，改用官方文档顶层入口（如 `https://kafka.apache.org/documentation/`）而非猜测的锚点路径。

## 写作基调

- 延续本仓库既有技术剖面的语域：判型式开局（"X 不是 Y，是 Z"一类的一句话结论先行），然后展开机制，最后落到真实项目怎么做、为什么这么做。
- 每个变体机制小节必须**点名真实项目**（这是「架构原理」与「主题视角」的核心区别——主题视角讲算法本身不点名，这里必须点名）。
- 如某变体是"概念参考、本仓库/本会话未做源码级核实"（例如 Dynamo/Cassandra），必须在该机制小节正文与对应 SVG 图注中都如实标注，不要包装成已验证事实。
