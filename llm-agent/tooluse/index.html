工具调用是 Agent 触达外部世界的唯一出口——模型只会生成文本，所有「行动」都必须落到一次工具调用。它同时是能力放大器与风险汇聚点：接入越多能力越强、攻击面也越大。围绕「模型如何决定并发起一次动作」，沉淀出四种递进机制（结构化调用、工具路由、MCP、Code-as-Action），按工具规模/安全预算/编排复杂度组合使用，见生态图。

T1Function Calling · Schema 约束的结构化调用

结构化调用（Function Calling） 最基础可靠：Schema 声明工具→模型输出 JSON→程序校验后执行→结果回流。关键认知：工具描述与 Schema 本身就是 prompt，命名清晰+参数自解释+带示例直接决定调用正确率；校验须严格、失败要把可读错误喂回模型自修正。局限是工具增多则全量 Schema 塞爆上下文。见图。

T2工具路由 · 海量工具的检索式选择

工具路由（Tool Retrieval） 应对数百上千工具：工具描述向量化建索引，运行时按意图语义检索取 Top-k 候选，只把这一小撮 Schema 交模型精排。本质是「检索召回+模型精排」两级。阿喀琉斯之踵在召回层——漏召即等于工具失效，索引质量与召回策略是生命线。见图。

T3MCP 协议 · 标准化工具/资源接入层

MCP（Model Context Protocol） 标准化「接入」：无协议时 M 应用×N 工具是 M×N 适配成本；MCP 用 Host 跑 Client、工具方跑 Server、统一 tools/list、tools/call、resources 经 JSON-RPC 对话，一次实现任意复用，成本降为 M+N 且可热插拔。是工具生态的「USB-C」。代价是第三方 Server 带来供应链与权限风险，需 Server 侧统一鉴权。见图。

T4代码执行 · 沙箱内 Code-as-Action

Code-as-Action 把动作推到极致：模型直接生成代码在隔离沙箱执行，一次完成循环/分支/多工具组合（工具以函数库注入）。表达力与 token 效率远高于逐个 function call，适合复杂多步编排。代价是安全从「校验参数」升级为「隔离执行环境」硬约束——超时/内存/网络/系统调用全设限，绝不在主环境跑。见图。

⇄Tool Use · 核心机制差异对比

取舍主线是「规模与复杂度」：工具少用结构化调用，规模上千用路由，跨系统复用用 MCP，复杂编排用 Code-as-Action。各自风险不同——结构化怕 prompt 膨胀、路由怕漏召、MCP 怕供应链、代码执行怕沙箱逃逸。真实系统多为组合（MCP 接入+路由筛选+代码编排）。四维对照见图。

⚙Tool Use · 工程实现差异（真实框架落地取舍）

三条铁律：契约即接口——工具描述/Schema 就是 prompt，写好文档拿到一半准确率，输出强校验、失败可读回退；安全与权限——最小权限、危险操作人工确认、代码执行强制沙箱、警惕工具返回内容的提示注入（越权与注入是头号事故源）；可靠与观测——超时/重试/幂等，记录每次调用入参/结果/耗时，限流熔断防级联雪崩，结果回流闭合推理循环。详见图。

2025 前沿：MCP 已从「一种方案」变为事实标准——自 Anthropic 开源后被主流厂商与工具方普遍采纳，公开可用的 MCP Server 已达数千量级，覆盖数据库、代码仓、浏览器、云服务等，Agent 中间层的「USB-C」形态基本坐实。这带来两个工程重心迁移：其一，能力接入不再靠一个个手写适配，而是从 Server 生态里挑装，选型时更看重 Server 的可信度与权限边界；其二，工具供给爆炸后，工具路由（Tool Retrieval）与输出治理从可选项变为必备项——上千工具不可能全塞进上下文，且第三方 Server 的返回需统一裁剪、鉴权与提示注入防护，供应链安全成为头号治理面。
