@eco
模型知识封存在权重里，天生三短板：会过期、不懂私有数据、爱幻觉。**RAG（检索增强生成）** 让模型生成前先检索外部证据，把答案锚定在可溯源材料上。系统分两侧：离线侧分块/向量化/建索引（一次建库多次复用），在线侧对每个 query 检索/精排/压缩再拼进 Prompt 生成带引用答案。核心张力——**召回不足则答不全、召回过多则噪声淹没**，精度与召回的平衡是永恒命题。见生态图。

@g1
**索引构建**是离线一次性建库，检索质量天花板在此锁死。文档清洗→切块（Chunk）→Embedding 编码→连同元数据存向量库+建关键词倒排。关键在分块：块太大语义被平均稀释、块太小信息不完整。须按语义/长度合理切分、相邻块保留重叠防边界切断、附标题来源时间戳供过滤溯源。**垃圾进垃圾出**——建库疏忽后续技巧补不回。见图。

@g2
**混合检索**解决单一检索盲区：向量检索懂「意思对」（ANN 找语义相近，擅长同义改写，漏无语义精确串如「A-7734」）；**BM25** 关键词检索管「字面对」（倒排精确命中专有名词/编号/代码，答不了语义改写）。两路并行召回，用融合排序（如 **RRF** 按排名而非原始分归一化）合并成统一 Top-k。难点在不同评分体系的归一化与权重调参。见图。

@g3
**重排生成**是在线「精挑+作答」。召回后需 Rerank：向量检索双塔独立编码、排序偏粗；**Cross-Encoder** 把 query 与候选拼接深度打分、精准但慢。故两段式——快模型粗筛（召回 50）+慢模型精排取 Top-n。再做上下文压缩去冗，缓解「迷失在中间」（长上下文只关注首尾）。生成须约束「**仅依据证据、标注引用、无据则答不知道**」，是抗幻觉最后一闸。见图。

@g4
**图谱检索（GraphRAG）** 应对普通 RAG 的两类短板：多跳推理（沿实体关系链游走）与全局归纳（答案分散在成百上千块）。离线用 LLM 抽取实体关系构图、聚类为社区并分层生成社区摘要；在线局部问题定位实体多跳游走、全局问题聚合社区摘要归纳。代价是建图依赖 LLM 抽取、成本高、实体消歧影响质量。与向量 RAG **互补而非替代**——精确事实用向量，关系全局用图谱。见图。

@cmp
四线在流水线上分工：G1 索引建库定质量上限（切块不当全盘皆输）、G2 混合检索兼顾语义与字面（评分归一化调参）、G3 重排生成精挑并产可信答案（精排慢+仍可能幻觉）、G4 图谱专攻多跳与全局（建图成本高）。选型主线：G1 做扎实，G2+G3 为标准在线流水线，确有多跳/全局需求才升 G4。四维对照见图。

@eng
三支柱：**数据即根基**——分块贴合结构、Embedding 匹配领域、元数据支撑过滤溯源、索引增量更新（质量上限在建库锁死）；**抗幻觉即底线**——只依据证据、强制引用、无据拒答，配 Rerank+压缩降噪（证据充分却编造比不答更糟）；**评测即闭环**——检索看命中/召回率、生成看忠实度/相关性、端到端看可用性，并能分层归因「检索错还是生成错」。总纲：RAG 是数据+检索+生成约束+评测的系统工程。详见图。

**2025 前沿**：RAG 正从「一次检索、一次生成」的静态管线，走向**Agentic RAG**——把检索本身交给 Agent 主动编排：先判断该不该查、拆解复杂问题为多个子查询、按第一轮结果决定是否追加检索或换数据源，多轮迭代直到证据充分才作答（检索成为可反思的循环而非固定前置步）。同时受 MCP 生态推动，知识源从「单一向量库」解耦为**可插拔的多数据源**（向量库、SQL、API、图谱经 MCP Server 统一接入），Agent 按问题动态选源。这让 RAG 与推理循环、工具调用深度融合：检索不再是独立模块，而是 Agent 决策链上的一环——也因此评测须从「单轮检索命中」扩展到「多轮检索策略是否高效、是否过度检索烧预算」。
