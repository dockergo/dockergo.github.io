记忆系统要解决根本矛盾：模型上下文窗口既有限又短暂（一段「工作记忆」，会话结束即清空）。要让 Agent 跨会话记住该记住的，需在窗口外搭三层协作——短期记忆保住近期上下文、长期记忆持久化并按需召回、记忆管理决定写入/遗忘/去重。核心张力：记得越多未必越聪明，噪声记忆反污染检索，「写入」与「遗忘」同等重要。见生态图。

M1短期/工作记忆 · 对话缓冲与滚动摘要

短期记忆解决「当前会话如何在有限窗口保持连贯」。对话缓冲原样带最近若干轮，撑爆窗口后引入滚动摘要——早期对话压成摘要（保留目标/已确认事实/关键决策）、近期保留原文。送模型的是「早期摘要+近期原文」，卡在 token 预算内又兼顾保真。权衡在摘要激进程度：压越狠越省钱、越可能丢后续细节。见图。

M2长期记忆 · 向量化存储与语义检索

长期记忆突破窗口容量：记忆片段经 Embedding 编码为向量，连同原文+元数据存入向量库；用时 query 编码后 ANN 检索召回 Top-k 拼进上下文。写入与读取以向量库为枢纽，让 Agent 跨会话调用历史经验。关键定律：召回质量 = 写入质量 × 检索质量——存进噪声只会更快喂回噪声，价值高度依赖前置写入治理。见图。

M3记忆管理 · 写入判定与遗忘衰减

记忆管理是防退化的治理层：写入判定把关（是否长期有用/是否已存在去重合并/是否敏感不入库，并打时间戳与来源）；遗忘衰减反向瘦身（久未命中降权、超容量淘汰最冷、新事实覆盖旧）。遗忘与记住同等重要——无限累积会让向量库塞满陈旧矛盾条目、检索精度不升反降。短期重要内容经此层固化进长期。见图。

⇄Agent Memory · 核心机制差异对比

短期与长期是互补两层：载体（窗口内 vs 外部向量库）、生命周期（随窗口滑动只活一次会话 vs 持久跨会话）、访问（全量在场 vs Top-k 召回）、瓶颈（窗口容量/token vs 检索精度/治理）。典型协作是闭环——短期中长期有用者固化进长期库，长期相关记忆检索回注短期，一进一出构成完整记忆循环。四维对照见图。

⚙Agent Memory · 工程实现差异（真实框架落地取舍）

三条铁律：写什么进记忆——只记长期有用的偏好/事实/结论，写前去重合并、敏感不入库、附时间戳来源（写入判定是质量第一闸）；怎么读回来——语义检索 Top-k 设相关性阈值宁缺毋滥、标注来源防幻觉、合并去冗（召回噪声直接污染推理）；何时遗忘——时间衰减+冷数据淘汰、新覆旧、设容量上限、支持用户主动忘记。核心：信噪比优先，重心不在「存」而在「治」。详见图。

2025 前沿：记忆正从「被动向量库」走向「自主治理」——按用途分三维（情景记忆 episodic 记事件、语义记忆 semantic 记事实、程序记忆 procedural 记技能/流程），按需分型召回而非一锅烩；A-MEM 等智能体记忆让 Agent 自己写笔记、建链接、动态改写旧记忆（类比 Zettelkasten 卡片盒），而非只读；MemGPT 的分页思想演进为分层记忆架构（热记忆常驻窗口、温记忆快取、冷记忆归档），由 Agent 自主调页。工程共识随之升级：「有无记忆的差距，往往大于换个更强模型的差距」。可观测性成硬指标：须能追踪每条召回记忆的来源与命中率、审计写入/遗忘决策、复盘「为何记住/为何忘记」，否则记忆系统会在无人察觉中悄然退化。
