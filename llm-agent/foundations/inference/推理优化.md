@eco

推理优化解决「训练好后如何又快又省地跑起来并扛并发」——百亿千亿参数、自回归解码天然串行、显存宝贵。围绕**更快、更省、更能扛并发**三目标:**KV 缓存** 免重算优化单请求延迟、**模型压缩** 缩体积降单位成本、**服务调度** 吃满 GPU 放大并发。见生态图。

@i1

**KV 缓存**是自回归解码提速基石。生成每个新 token 都需用到之前所有 token 的 K/V,不缓存则每步重算整个序列,约 **O(n²)**。做法:历史 K/V 存显存,每步只对新 token 算 Q 与缓存做注意力、追加新键值,单步降至 **O(n)**。空间换时间——**缓存显存随上下文线性增长**,催生 MQA/GQA 共享键值头、KV 量化、分页管理。见图。

@i2

**模型压缩**保精度前提下缩小模型。三主线:**量化**降数值精度(FP16→INT8→INT4),显存带宽成倍降,性价比最高(PTQ/QAT);**蒸馏**大模型软标签教学生小模型,以小体积近似大能力;**剪枝**去冗余权重/结构,结构化剪枝(整头整层)易转真实加速、剪后微调恢复精度。常组合使用,核心是精度-效率权衡。见图。

@i3

**服务调度**关注系统层「吃满 GPU」。传统静态批要等批内最慢请求、GPU 空转;**连续批处理 (in-flight batching)** 每步动态重组批次、请求一结束即插新请求,吞吐大增(vLLM/TGI 标配)。配套 **PagedAttention** 借虚拟内存思想把 KV 缓存切固定「块」按需分配:消除碎片、利用率近 100%,相同前缀块共享省显存,支撑更大批次更长上下文。代价是调度显存管理更复杂。见图。

@cmp

三构件职责分明:**KV 缓存**解「每步重算」(缓存历史只算新 token,代价显存线性增长)、**模型压缩**解「模型太大」(量化/蒸馏/剪枝降开销,代价少量精度)、**服务调度**解「GPU 空转」(连续批+分页显存提吞吐,代价系统更复杂)。一句话:缓存免重算、压缩降开销、调度提吞吐。三维对照见图。

@eng

「先压模型、再优解码、后扛并发」三支柱:① 按目标硬件选量化精度(INT8/INT4),资源紧可蒸馏/结构化剪枝,压后评测精度回归;② 解码默认开 KV 缓存,长上下文用 MQA/GQA、必要时量化缓存,配 FlashAttention、投机解码,盯首 token 延迟与吞吐;③ vLLM/TGI 连续批拉满 GPU,PagedAttention 管显存,按 SLA 多副本负载均衡。权衡:端侧压缩优先、在线高并发靠连续批+PagedAttention、长文本靠 GQA+KV 量化+分页显存。
