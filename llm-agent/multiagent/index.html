当单 Agent 上下文塞不下整个任务、一个模型既规划又执行还自评力不从心时，把「全能 Agent」拆成多个专长 Agent 协作——这就是多智能体系统。它回答三个正交问题：如何组织谁指挥谁（编排拓扑）、扮什么角色如何制衡（角色分工）、如何交换信息（通信协作）。前提：多 Agent 不是银弹，用成倍成本、更复杂拓扑、更难调试换更强能力——单 Agent 解决不了时才引入。见生态图。

A1编排拓扑 · 监督者 vs 去中心化网络

编排拓扑回答「谁指挥谁、信息如何流动」。两极端：监督者模式中心化，一个监督者拆解派发再收集，流程可预测/易追责/便调试，代价是自身成瓶颈单点；去中心化网络对等直连自主协商，灵活抗单点却易失控/难收敛。生产系统多首选监督者（更需可控可观测）。无论哪种都要设最大轮数与预算防无限对话。见图。

A2角色分工 · 规划者/执行者/评审者

角色分工把单体按职责拆专家团队，经典是规划者/执行者/评审者三角：规划者只想「做什么」（拆带依赖子任务）、执行者只管「怎么做」（调工具写代码）、评审者只问「对不对」（校验放行）。四重收益：窄职责系统提示词降幻觉（认知减负）、评审独立形成「生成—校验」对抗闭环（制衡纠错）、单独升级替换（可替换）、日志定位到环节（可观测）。代价是角色越多 token 越高，粒度须匹配复杂度。见图。

A3通信协作 · 黑板 + 消息传递

通信协作回答如何交换信息。黑板模式让所有 Agent 读写同一共享状态，解耦易加入新 Agent，适合共同打磨同一产物（如共写文档），但需锁/版本控制防并发写冲突、警惕状态膨胀；消息传递是显式请求/响应，天然可追溯/审计/重放，是生产主流，代价是拓扑复杂+路由开销。关键：需共享草稿用黑板，需审计重放用消息传递。见图。

⇄Multi-Agent · 核心机制差异对比

三大机理并排看：编排拓扑在集中（单点瓶颈）与去中心（难收敛）间权衡、角色分工用规划/执行/评审闭环换质量（轮次 token 上升）、通信协作在黑板（并发冲突）与消息（路由复杂）间权衡。本质都在同一根轴取舍——能力越强越灵活，可控性与成本压力越大。落地顺序：先定拓扑划边界、再定分工拆能力、最后定通信约信息契约。四维对照见图。

⚙Multi-Agent · 工程实现差异（真实框架落地取舍）

三条铁律：可控即底线——默认单 Agent，每个设最大轮数/预算/超时，优先监督者拓扑并保留人工介入，副作用操作二次确认（反例：放任互调烧光预算）；成本即约束——多 Agent 成本延迟成倍，小模型跑执行/评审、大模型只规划，可并行则并行、缓存中间结果；可观测即前提——全链路 trace 记录各 Agent 输入/输出/工具调用，消息优于黑板便于审计重放，失败能区分规划/执行/评审哪环，评测以最终产物质量为准。详见图。

2025 前沿：协作规模从「三五个角色」跃升到成团编排——一个主 Agent 动态派生数个到十几个子 Agent 并行攻坚（Agent Teams），乃至上百子智能体的蜂群（Swarm）分片处理超大任务，靠上下文隔离让每个子 Agent 专注一小块、避免共享窗口被撑爆。随之而来的核心挑战不再是「能不能拆」，而是可控性与可观测性：企业落地时对「能否追踪每个子 Agent 在做什么、能否在失控前叫停」的关切，已超过对成本与延迟的关切（见 LangChain《State of AI Agents》调研）。故成团协作必须配套：分层监督（主管子、子管孙）、全局预算熔断、逐 Agent trace 与统一裁决层，否则规模越大越不可控。
