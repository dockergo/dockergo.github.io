@eco

栈、队列、双端队列是给**线性表**加上「只能在端点操作」纪律后的三个家族成员，用灵活性换来强语义与恒定操作代价。区别只在**开放哪些端**：栈单端进出（LIFO）、队列两端分工（队尾进队首出，FIFO）、双端两端皆可进出（前两者的超集）。第二个正交维度是**底层载体**——数组连续内存缓存友好但满需扩容搬移，链表端点增删恒定 O(1) 无上限但多付指针且随机访问 O(n)；故每个结构均给数组版与链表版两种实现。

@q1

**栈**：一个开口，push/pop 都在栈顶，LIFO，两种实现均 O(1)。数组版以尾部为栈顶（`append`/截尾，头部操作要 O(n) 搬移），代价是装满触发扩容复制——即「均摊」二字来源；链表版以 `container/list` 的 Back 为栈顶，恒定 O(1) 无扩容抖动，代价是每结点多存双指针且缓存局部性差。两版行为一致，差别仅栈顶物理落点。栈是函数调用、表达式求值、括号匹配、DFS、撤销等场景骨架。

@q2

**队列**：FIFO 需两端分工。朴素数组出队后左移对齐是 O(n)，`arrayQueue` 用**环形数组**根治——`front` 出队仅前移 `(front+1)%cap`，`rear = (front+queSize)%cap` 取模回绕复用前段空格，入队出队均 O(1)（物理上可能 `rear < front`，按 `(front+i)%cap` 还原逻辑序）。易错点：仅用 `front == rear` 无法区分空/满，故改用**显式计数** `queSize`（0 为空、等于容量为满）；本实现满则拒绝入队不自动扩容。链表版 `PushBack`/`Remove(Front)` 无上限无取模，代价是指针内存。环形数组宜容量可估、追吞吐；链表宜数量剧烈波动。

@q3

**双端队列**：两端皆可 push/pop，环形数组关键是双向回绕索引 `index(i) = (i + cap) % cap`，使 `i` 越过尾部或越过头部（变负）都落回 `[0, cap)`。四操作对称，`pushFirst` 时 `front` 从 0 减到 -1 会折回 `cap-1`（头部入队写到数组末尾的回绕现象），全部 O(1)。链表版 `linkedListDeque` 直接映射 `PushFront/PushBack/Remove(Front/Back)`，无取模无容量管理，代价仍是每结点双指针。它是栈与队列的统一超集，滑动窗口最值等依赖其两端 O(1)。

@cmp

两条正交维度并排看：**操作端**——栈 LIFO 单端、队列 FIFO 两端、双端为超集；**载体**——数组连续内存、随机访问 O(1)、缓存好、零额外开销，但满需扩容搬移 O(n) 且队列/双端靠取模回绕；链表任端增删恒定 O(1)、无上限、永不搬移，但随机访问 O(n)、每结点多付 1~2 指针、缓存不友好。选型：容量可估追吞吐选环形数组，数量波动大要恒定 O(1) 选链表；两维度可自由组合。详见对比图。
